# plans/

[中文](README.md) | [English](README.en.md)

这里只放**还在某个 PR 里协作的过程笔记**。产品契约、架构、API 和数据库说明仍在 `docs/`；已经批准的规则在 specs 的 ADR。本目录的 `README.md` 与 `README.en.md` 是仓库约定，长期保留。每个主题子目录都是中间产物。

业界通常把会过期的实现进度留在 PR 说明或单独的工作笔记里，不写进长期文档。长期留下的是决策（ADR）和仍被代码使用的契约。Kubernetes KEP、Rust RFC 会归档，是因为它们本身是决策；阶段做到哪一步不是决策。因此本仓库选择：过程笔记可以提交到功能分支上，方便其他人和其他会话接着做；**该项工作合并前删除对应子目录**。不要把笔记放进 `docs/`，也不要在 `docs/INDEX.md`、`README` 或架构文档里把它写成依据。

## 怎么用

- 一个进行中的主题一个目录：`plans/<主题>/`。主题用小写短横线，例如 `runtime-control/`。
- 目录里只记录当前阶段、已落地事实、必读链接和不要做什么。规则以 ADR 或正式文档为准；笔记与之冲突时，笔记无效。
- 可以随该功能的 PR 提交。不要放密钥、令牌或本机路径。
- 该主题的最后一个 PR 在合并前删除整个 `plans/<主题>/`。需要留下来的行为写进代码、测试、迁移或 specs 的证据，不在这里收成第二份规格。
- 合并后的 `main` 上，除本说明外，`plans/` 里不应再有已完成主题的目录。

- `docs/migrations/` 下的阶段记录和 issue-board 实现日志
