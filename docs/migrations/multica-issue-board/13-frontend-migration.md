# 13 — Formal frontend migration

## Goal

Migrate the reference frontend from `cloud前端/` into `cloud/frontend/` as Ora Cloud's **official
web frontend** — move/reuse/adapt, not rewrite. It must belong to `cloud`, install/build/run on its
own, and talk to the real backend over the HTTP API; no symlinks and no cross-directory imports into
`../cloud前端`.

## What the frontend is

React 19 + TypeScript + Vite + Tailwind CSS 4 + TanStack Query. The API layer (`src/api/`) is
generated by orval from `api/openapi.json`, so the frontend and backend share one contract. Auth
reuses Cloud's dual-JWT: the browser holds only a session cookie + user profile; `cmd/ora-web`
signs tokens server-side (the browser is untrusted). Dev proxy forwards `/api`, `/internal`,
`/healthz` to `:8080`.

## Issue features implemented against the real backend

- Board (Kanban): columns, cards, drag-to-move via fractional `position` (`/issues` + `/move`).
- Issue CRUD, status, priority, title, description, assignee, parent/sub-issue, labels, comments,
  subscribers, search (`?q=`), batch update, saved views, grouped views, `properties`.
- Wave 3A surfaces: `assigneeType`/`assigneeId`/`projectRef` on issues; comment `parentId` /
  `authorType` / `authorId` / `seq`; IssueRun create/list/get; IssueContextRef list/create/delete.
- New code prefers `assigneeType`/`assigneeId` over the legacy `assigneeUserId`.

## Deliberately unavailable (shell / "Not connected" / "Coming later")

These have no backend capability yet, so the frontend shows a disabled or unavailable state instead
of faking production behavior:

- Assignee of type `agent` / `team` — no resolver; UI marks them unavailable.
- Project details — `projectRef` is an opaque UUID; the UI shows `projectRef` and
  "Project details unavailable".
- Runs — POST `/issues/:id/runs` is presented as "Run created / queued", **not** "agent executing".
- Context refs — list/add/remove only (no smart hydration of referenced objects).
- Execution, realtime/WebSocket, PR integration, execution logs, full Timeline — placeholders.

## Not in scope this pass (do not build)

Wave 3B ports, the (superseded) 0008 simulator catalog, fake Agent/Team/Workflow/Executor backends, real agent
execution, workflow backend, realtime, PR backend, execution-logs backend, notification system,
LLM/runtime.

## Demo vs formal

- `cmd/demo-issue-board-web/` — single-file HTML Kanban demo, no frontend dependency, server-side
  JWT signing. Kept for manual HTTP verification of the Issue API.
- `frontend/` — the formal product frontend, replacing the reference `cloud前端/`.

The two coexist; the demo is not the product UI.

## Verification

- Backend: `go build ./...` and `go test ./internal/... ./cmd/...` PASS.
- Frontend: `npm ci` / `npm run dev` / `npm run build` / `npm run check` (lint, typecheck, tests)
  are required; they need Node >= 24 (`.node-version` + `engine-strict`), which was not available in
  the migration environment — see the commit notes for the exact state.
